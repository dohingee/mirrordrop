# 첫 출시 순서표 (MirrorDrop 1.0)

빌드 16 기기 시험이 끝난 뒤부터 App Store에 "출시"될 때까지 할 일을 순서대로 적은 **유일한 출시 문서**다. 2026-11-22 작성.
- 처음 설정(Apple 앱 ID, GitHub 비밀값, TestFlight 올리는 법)은 `docs/SETUP.md`, 스토어에 넣을 글은 `docs/store/ko.md`(한국어 + 심사 메모)·`docs/store/en.md`(영어), 광고 규칙은 `docs/MONETIZATION.md`, 심사 위험 판단은 `docs/SPEC.md`.
- 표시: 🤖 = Claude(웹 관리 화면도 Claude가 내장 브라우저로 직접), ✋ = 사용자만 할 수 있는 것(로그인·2단계 인증·로봇 확인, 결제·세금·계좌·신분 정보, iPhone을 손에 들고 하는 시험, 촬영).
- 로그인할 계정: Apple(App Store Connect)은 Apple 개발자 계정 주인, Google(AdMob·Firebase)은 **밖에 안 보이는 관리용 구글 아이디**(사용자 전역 규칙). 공개 저장소이므로 이 문서에도 그 주소를 적지 않는다.
- 밖으로 나가는 일(웹 페이지 게시, 심사 제출, 출시, 약관 동의)은 🤖가 하되 **그 자리에서 한 번 사용자 확인**을 받는다.

## 2. 🤖 빌드 17 코드 마무리
### 2-1. 이미 한 것 (2026-11-22)
- 출시 빌드 정리(심사 2.1 "완성된 앱"): 고급·진단에서 PoC 시험 도구를 뺐다. "테스트 A · 인터넷 샘플 영상"(Apple 샘플 영상을 인터넷에서 틀어 "화면은 집 Wi-Fi 밖으로 안 나감" 설명과도 어긋났음)과 "지연 실험" 고르기를 없앴다. L3가 고정 설정이고, 빌드 16까지 고른 값은 빌드 17에서 한 번 지운다(`LatencyPreset.l3ResetKey`). 진단·문제 보내기·지연 측정 시계는 그대로.
- 앱 안 개인정보 처리방침 링크(심사 5.1.1): 첫 화면 맨 아래와 고급·진단 "정보" 칸. 주소는 `AppLinks`(`ios/MirrorDrop/UI/AdvancedView.swift`) 한 곳.
- 첫 화면 맨 아래 상표 문장: "Google Cast는 Google LLC의 상표이며 …"(Google Cast 가이드라인의 상표 표기).
- 버전 1.0.
- 스토어 스크린샷 데모 모드(7번).

### 2-2. 다른 에이전트가 할 것과 지켜야 할 약속
광고 코드와 영어 화면은 따로 만든다. 아래 글자·자리는 웹 페이지·심사 메모에 이미 적혀 있으므로 **그대로** 쓰거나, 바꾸면 그 문서들도 함께 고친다.
- 광고(`docs/MONETIZATION.md` 그대로): 첫 화면 아래 배너(보내는 중·시작하는 중에는 숨김), 시작 전 전면 광고(하루 1번, 5가지 조건), 앱 열기·보상형 광고 없음, 확장에는 광고 없음.
- 고급·진단 화면에 **"광고 개인정보 설정"**(영어 "Ad privacy settings", UMP의 privacy options. 동의가 필요한 지역에서만 보여도 됨)과 **"광고 신고"**(영어 "Report an ad", 메일 `kimyeoware@gmail.com`로)를 둔다. 처리방침 6번·지원 페이지·심사 메모가 이 이름을 쓴다.
- 영어 화면에서 "문제 보내기"는 **"Report a problem"**(영어 지원 페이지가 씀).
- `Info.plist`(`ios/project.yml`): `GADApplicationIdentifier`, `SKAdNetworkItems`(Google이 공개한 목록), `NSUserTrackingUsageDescription`(한국어·영어). 앱 `PrivacyInfo.xcprivacy`를 Google 광고 SDK와 맞춘다(SDK가 자체 매니페스트를 갖고 있는지 확인).
- 순서: UMP 동의 → ATT 창. 거부해도 모든 기능. 심사 빌드에서 시험 광고를 보일지(팔자노트처럼 TestFlight·심사 환경은 시험 광고)는 광고 담당이 정하고, 정한 대로 심사 메모 ADS 줄을 고친다.
- **데모 모드에서는 광고를 띄우지 않는다**(`DemoMode.current != nil`이면 배너·전면 광고·UMP·ATT를 건너뜀). 스토어 스크린샷에 시험 광고가 찍히지 않게.
- 영어 화면을 만들면 `ios-launch-check.sh`에 영어 스토어 캡처(`-AppleLanguages "(en)"`으로 `store-sending`·`store-connected`·`guide`)를 더한다.

## 3. 광고 계정 준비 (AdMob)
1. ✋ AdMob **결제 프로필**: 이름·주소·은행 계좌와 미국 세금 정보(개인 W-8BEN)를 넣는다. 금융·세금 정보라 사용자만 한다. 이미 팔자노트 때 했으면 넘어간다(광고 계정은 한 사람에 하나, 같은 계정을 쓴다).
2. 🤖 AdMob → 앱 → 앱 추가: iOS, "스토어에 아직 없음"으로 등록(이름 MirrorDrop). 출시 뒤 스토어와 연결한다(13번).
3. 🤖 광고 단위 2개: 배너(첫 화면), 전면(시작 전). ID는 광고 담당 에이전트에게 넘긴다(앱 ID·광고 단위 ID는 비밀값이 아니라 코드에 넣어도 된다).
4. 🤖 차단 설정: 광고 콘텐츠 등급 최대 **T(청소년)**, 민감 분야(도박·데이트·성인 등) 차단.
5. 🤖 개인정보 보호 및 메시지(Privacy & messaging):
   - **GDPR 메시지**(EEA·영국·스위스): 언어 영어·한국어, 개인정보 처리방침 주소 `https://mirrordrop-app.web.app/en/privacy.html`, 광고 파트너는 Google 기본 목록.
   - **IDFA 설명 메시지**(ATT 창 앞에 왜 묻는지 보여 줌): 만든다. 동의율이 오르고 UMP가 ATT 창까지 이어서 띄운다.
   - **미국 주 규정 메시지**(캘리포니아 등): 만든다. "광고 개인정보 설정"에서 "내 정보 판매·공유 거부"를 고를 수 있게 된다.
   - 만들 때 "게시"(Publish)는 앱 코드가 준비된 뒤 사용자 확인을 받고 누른다.

## 4. 🤖 웹 페이지 올리기 (처리방침·지원·app-ads.txt)
파일: `web/hosting/`(`index.html`, `privacy.html`, `support.html`, `en/` 아래 같은 세 개, `app-ads.txt`), 설정 `web/firebase.json`·`web/.firebaserc`.
1. 🤖 Firebase 콘솔(관리용 구글 아이디, ✋ 로그인만)에서 새 프로젝트 `mirrordrop-app`을 만든다(구글 애널리틱스 **끔**). 이미 쓰이는 ID면 `mirrordrop-ios` 등으로 정하고, 바뀐 ID를 `web/.firebaserc`, 앱의 `AppLinks`, `docs/store/ko.md`·`en.md`, 심사 메모, `web/hosting/` 안의 주소에 한꺼번에 고친다(**빌드 17을 만들기 전에**: 앱 안 링크가 이 주소다).
2. 🤖 처리방침을 마지막으로 맞춘다: 7번 시뮬레이터 검사가 가져온 Google Cast SDK의 개인정보 파일(`ci-results`의 `cast-sdk-privacy/`, `NutritionLabel.txt`)을 읽고, 처리방침 2-마("Google Cast 기능")와 아래 App Privacy 표를 그 내용과 맞춘다. 광고 코드가 실제로 하는 일(동의 지역, 버튼 이름)과도 맞춘다. 내용이 바뀌면 시행일을 올린다.
3. 🤖 사용자 확인 뒤 PC에서 게시: `cd web && firebase deploy --only hosting --project mirrordrop-app` (✋ Firebase CLI 로그인이 안 돼 있으면 `firebase login`만 사용자가).
4. 🤖 확인: `https://mirrordrop-app.web.app/privacy.html`, `/support.html`, `/en/privacy.html`, `/en/support.html`, `/app-ads.txt`가 열리는지. `app-ads.txt` 한 줄은 AdMob 계정의 게시자 ID다(팔자노트 사이트에 이미 공개된 같은 값, 비밀 아님).

## 10. 🤖 App Privacy (앱 개인정보 보호)
- **개인정보 처리방침 URL**: 영어 `https://mirrordrop-app.web.app/en/privacy.html`, 한국어 `https://mirrordrop-app.web.app/privacy.html`(언어별 칸).
- "데이터를 수집합니까?" → **예**(광고 때문). Apple의 "수집"은 기기 밖(개발자나 다른 회사)으로 보내 오래 두는 것이다.
- 앱 자체 코드(검사함, 2026-11-22): 분석·충돌 보고 SDK가 없다(`ios/project.yml`의 패키지는 Google Cast뿐). 화면·소리는 집 Wi-Fi 안에서 TV로만 가고(사설 주소만 받음) 저장하지 않는다. 진단 기록은 iPhone 안에만 있다. → 수집 아님.
- "문제 보내기"는 사용자가 공유 창에서 직접 보낼 곳을 고르는 드문 선택 기능이고 광고·추적에 쓰지 않으므로, Apple의 "선택적 공개"(optional disclosure) 조건에 맞아 적지 않는다. 메일 문의도 같다.
- 광고(Google AdMob)가 모으는 것. 근거: Google "Apple App Store data disclosure"(https://developers.google.com/admob/ios/privacy/data-disclosure, 2026-11-22 확인). Google은 "연결·추적" 여부를 대부분 밝히지 않으므로 맞춤 광고를 쓰는 앱 기준으로 넓게 답한다(팔자노트와 같음).

|---|---|---|---|
| 식별자 → 기기 ID | 제3자 광고, 분석 | 예 | **예** |

## 거절되면
- 🤖 해결 센터의 메시지를 그대로 읽고(✋ 로그인만), 지침 번호별로:
  - **2.1(기능을 시험할 수 없음)**: 시연 영상 주소가 열리는지 확인하고, 영상을 더 분명하게(처음부터 끝까지, TV 화면 크게) 다시 찍어 답장한다. 기기를 빌려주겠다는 식의 지킬 수 없는 약속은 하지 않는다.
  - **4.3(b)(흔한 앱)**: 같은 빌드를 그대로 다시 내지 않는다(Apple이 반복 제출을 경고, 팔자노트 2026-11-16 거절의 교훈). 해결 센터에 **한 번** 답장으로 다른 점(심사 메모 WHAT MAKES IT DIFFERENT)을 설명하고 "무엇을 바꾸면 되는지" 묻는다. 그래도 안 되면 앱 심사 위원회(App Review Board)에 이의를 낸다. 앱 이름만 바꿔 새로 내지 않는다(SPEC 결론).
  - **2.3(설명이 실제와 다름)·4.1(c)/5.2(상표)**: 지적된 문장·스크린샷만 고친다(글은 심사 없이 못 바꾸므로 새로 제출).
  - **5.1.1/5.1.2(개인정보·추적)**: 처리방침 링크, App Privacy 표, 동의 순서(UMP → ATT, 거부해도 기능)를 지적대로 맞추고 코드가 바뀌면 새 빌드.
  - **2.5.14·2.5.4·2.5.1**: 메모의 HOW IT WORKS·PERMISSIONS 문단을 근거로 답한다(시스템 방송 선택기, 백그라운드 모드 없음, 공개 API만).
  - **광고(2.5.18)**: 광고 자리가 버튼과 겹치거나 보내는 중 나온다는 지적이면 코드를 고친다.
- 고친 내용과 날짜를 `docs/SPEC.md` 해당 지침 줄에 적는다(다음 업데이트에서 같은 일이 없게).
