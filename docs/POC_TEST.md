### 지연 실험 (빌드 13부터)
설정마다 빌드를 새로 만들지 않도록 앱에 **지연 실험** 선택지를 넣었다. 방송을 멈춘 상태에서 고르고, 방송을 다시 시작하면 적용된다.
| 설정 | 조각 | 재생목록 | 기타 |
|---|---|---|---|
| L0 | 1초 | 4개 | 빌드 13까지의 기본값 |
| L1 | 1초 | 3개 | |
| L2 | 1초 | 3개 | 재생목록에 "끝에서 2초 앞부터 재생" 표시(EXT-X-START) |
| L3 | 0.5초 | 6개 | 다음 빌드부터 기본값 |

각 설정마다: 방송 시작 → TV에 뜨고 30초 기다림 → 지연 측정 시계 사진 1장 + **진단 → TV 재생 위치**의 "라이브 끝에서 X초 뒤" 숫자 → 진단의 "마지막 조각" 길이(L3은 약 0.5초여야 함).
- L0: 사진 **4.0초**(2026-11-21 07:55~56, TV 07:55:57.38 / iPhone 07:56:01.38) · TV 재생 위치 ___초 · 사용 소감: **못 쓸 수준**(시작 직후. 시간이 지나면 괜찮음, 아래 설명)
- L1: 사진 ___초 · TV 재생 위치 ___초 · 사용 소감: 처음엔 "괜찮음", 다시 써 보고 **못 쓸 수준**(시작 직후. 시간이 지나면 괜찮음, 아래 설명)
- L2: 사진 ___초 · TV 재생 위치 ___초 · 사용 소감: **못 쓸 수준**(시작 직후. 시간이 지나면 괜찮음, 아래 설명)
- L3: 사진 **약 4.3초**(2026-11-21, TV 08:12:24.84 / iPhone 08:12:29.1, iPhone 쪽 숫자가 흐려 ±0.1초) · TV 재생 위치 **2.4초**(끝 30.1, 위치 27.6, 같은 08:12) · 마지막 조각 ___초 · 끊김 [ ] 없음 [ ] 있음 · 사용 소감: 괜찮음, **화면이 가장 부드럽게 움직임**
- 사용 소감은 사용자가 빌드 13에서 직접 써 보고 알려 준 것(2026-11-21). "화면이 제일 부드럽게 움직이는 게 L3"(사용자). 이어서 사용자 설명: L0·L1도 시간이 지나면 괜찮아지지만, 처음부터 바로 괜찮은 것은 L3("사용자는 그리 긴 시간을 기다려주지 않아"). Claude의 추론: L0·L1(1초 조각)은 방송 시작 직후 한동안 부드럽지 않다. L2의 시간 경과 모습은 기록 없음. 지연은 L0 4.0초·L3 4.3초로 비슷했다.
- 해석(L3): 지연 약 4.3초 = TV 재생기가 라이브 끝에서 일부러 뒤에 서는 시간 약 2.4초 + 그 밖(인코딩·조각 완성·TV가 재생목록을 다시 받기까지·디코딩) 약 1.9초. 0.5초 조각에서도 재생기가 약 2.4초 뒤에 서므로, 조각을 줄여도 기본 수신기의 이 몫은 줄지 않는다(L0 4.0초 ≈ L3 4.3초와 맞음). 이 몫은 수신기 쪽 설정이라 기본 수신기로는 바꿀 수 없고, 커스텀 수신기에서 재생기 설정으로 줄일 수 있다.
- 결정(2026-11-21): 처음엔 기본값을 L1로 정했다가, L1도 부드럽지 않다는 소감을 받고 **L3**로 바꿈(`LatencyPreset.default`). L3는 조각이 0.5초라 키프레임(통째 그림)이 2배 자주 들어가 같은 데이터량에서 화질이 조금 떨어질 수 있으니 다음 빌드에서 글씨·사진 선명도를 본다. 빌드 16부터는 예전에 고른 값을 처음 한 번 지우고 L3로 시작한다(`LatencyPreset.l3ResetKey`). 그 뒤에 고급·진단에서 고른 값은 그대로 남는다. 왜 L0·L1이 시작 직후에만 덜 부드러운지는 아직 모른다.
- 결정(2026-11-21, 사용자): 지연은 **약 4초로 진행**한다. 커스텀 수신기(Cast 등록 5달러)는 지금 하지 않고, 필요해지면 나중에 붙인다.
