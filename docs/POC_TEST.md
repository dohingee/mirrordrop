# PoC 기기 시험 체크리스트

준비물: TestFlight로 설치한 MirrorDrop, Google Cast 기기(TV·스틱), 같은 Wi-Fi, 다른 휴대폰(사진 찍기용, 지연 측정).

적는 법
- 각 항목의 `[ ] 통과` / `[ ] 실패` 중 하나에 `x`를 칩니다.
- 실패하거나 이상하면 **진단 → 로그 전체 복사**를 눌러 Claude에게 그대로 붙여 넣어 주세요. (주소의 비밀 토큰은 자동으로 빠집니다.)
- 시험한 날짜, iPhone 기종·iOS 버전, Cast 기기 이름(예: TV 모델명)을 맨 아래에 적어 주세요.

## 테스트 A · 인터넷 샘플 영상 (수신기와 연결이 정상인지)
1. 샘플 **Apple bipbop (fMP4)** 선택 → **TV로 보내기**
2. TV에 bipbop 화면(숫자와 색 막대)이 나오는지 봅니다. **TV 재생 상태**도 확인합니다.
3. 샘플을 **Apple bipbop (TS)** 로 바꿔 한 번 더 합니다.

- [ ] 통과 / [ ] 실패 — fMP4 샘플이 TV에서 재생된다
- [ ] 통과 / [ ] 실패 — TS 샘플이 TV에서 재생된다
  - 메모 (안 되면 "TV 재생 상태"와 빨간 오류 문구):

> 샘플 주소가 바뀌어 안 열릴 수도 있습니다. 그때는 주소 칸에 다른 공개 HLS 주소를 붙여 넣어 시험합니다.

## 테스트 B · 내 iPhone 화면 → TV (이번 PoC의 핵심)
1. **준비되면 자동으로 TV에 띄우기**가 켜져 있는지 확인합니다. (앱 소리 포함은 **끈 상태**로 먼저)
2. **테스트 B**의 동그란 버튼 → **MirrorDrop** 선택 → **방송 시작** → 3초 카운트다운
3. 앱 화면에서 "공유 상태"가 `영상 조각 만드는 중…` → `방송 중`으로 바뀌고 "만든 조각"이 늘어나는지 봅니다.
4. TV에 iPhone 화면이 뜰 때까지 **앱에 머뭅니다.** (자동으로 안 뜨면 **지금 TV에 띄우기**)
5. 뜨면 홈으로 나가 **사진** 앱을 열고 사진 몇 장과 영상 하나를 봅니다.

- [ ] 통과 / [ ] 실패 — 공유 상태가 "방송 중"이 된다
- [ ] 통과 / [ ] 실패 — **진단 → 서버 요청**에 TV 주소(내 iPhone이 아닌 192.168.x.x 등)가 나타난다 (= TV가 iPhone에서 영상을 가져갔다)
- [ ] 통과 / [ ] 실패 — TV에 iPhone 화면이 나온다
- [ ] 통과 / [ ] 실패 — 사진 앱으로 옮겨도 TV 화면이 계속 따라온다
- [ ] 통과 / [ ] 실패 — 화면을 가만히 둬도(정지 화면) 1분 이상 끊기지 않는다
- [ ] 통과 / [ ] 실패 — 10분 동안 켜 두어도 멈추지 않는다
  - 메모 (TV가 요청을 보냈는지 여부가 특히 중요합니다):

> 판단 도움말
> - 서버 요청이 **0개**: TV가 iPhone 주소를 열지 않았습니다. (https 수신기의 http 차단 = "혼합 콘텐츠" 의심, `docs/PLAN.md` 3번)
> - `live.m3u8`, `media.m3u8`만 반복되고 `seg…m4s`가 없음: 재생목록 단계에서 막힘
> - `seg…m4s`까지 계속 오는데 화면이 검음: 영상 형식 문제
> - **iPhone 안에서 서버 점검** 버튼이 실패: iPhone 서버 자체 문제

### (c) DRM(FairPlay) 서비스 (예: Netflix, Disney+, Apple TV+ 웹)
**검은 화면이나 재생 거부가 나오는 것이 정상입니다.** 저작권 보호 기능 때문이며, 앱 버그가 아니고 우회하지도 않습니다.
